# 快捷键对照（SuperGit vs Sublime Merge）

> 目的：把当前 SuperGit 的键位记录下来，和 Sublime Merge 的默认键位逐条对照，决定「取其优势」时先补哪些。
>
> 数据来源：
> - SuperGit：`internal/lobedesk/shortcuts.go` 的 `shortcutTable()` 是窗口级键位的唯一来源（第 264 轮起），设置页「快捷键」卡片直接读这张表；`KeyShortcuts` 与各页搜索框的 `ShortKey` 仍是各控件的本地绑定（2026-11-13 第 160 轮核对，第 182 轮逐条复核）。
> - Sublime Merge：本机 `/Applications/Sublime Merge.app/Contents/MacOS/Packages/Default - Merge.sublime-package` 内的 `Default (OSX).sublime-keymap`，共 113 条绑定，其中大量是按上下文生效的（同一按键在不同面板做不同事）。

## 差异清单

| 动作 | Sublime Merge | SuperGit | 结论 |
| --- | --- | --- | --- |
| 搜索提交 | ⌘F | ⌘F | 一致 |
| 搜索分支/标签 | ⌘F（搜索框） | ⌘F | 一致 |
| 提交 | ⌘↵ | ⌘↵ | 一致 |
| 首选项 | ⌘, | ⌘, | 一致 |
| 暂存文件 | ↵ / ⇧↵ | Space / ⇧↵（↵ 留给「打开文件」） | 刻意不同：SuperGit 的 ↵ 是默认动作，Space 更接近文件列表的快速开关 |
| 刷新 | F5 | ⌘R | 键位不同，功能齐全 |
| 切换页面 | ⌘1…⌘4 | ⌘1…⌘4 | 一致（历史页承载工作树行） |
| 命令面板 | ⌘P | 无 | 缺。体量大，需要单独立项 |
| 后退/前进 | ⌘← / ⌘→ | 无 | 缺。可从「父提交」跳转延伸出导航栈 |
| 父/子提交 | ⌥↑ / ⌥↓ | 无（详情里有父提交按钮） | 缺。可先给父提交按钮补键位 |
| 跳到 HEAD | ⌘0 | 无 | 缺。历史页有用，成本低 |
| 引用筛选 | ⌘⇧F | 无（点页头下拉） | 缺。成本低 |
| 文件筛选 | ⌘⌥F | 无（仅从文件历史进入） | 缺。与引用筛选同批 |
| 暂存全部 / 取消暂存全部 | ⌘⇧A / ⌘⇧R | 无（只有按钮） | 缺。成本低 |
| Stash / Pop Stash | ⌘S / ⌘⇧S | 无（Stash 页按钮） | 缺。⌘S 在别处通常表示「保存」，需确认是否占用 |
| 丢弃改动 | ⌫ / ⇧⌫ | 无（右键菜单） | 缺。破坏性操作，键位要谨慎 |
| Pull | F7 / ⌥⌘↓ | 无 | 缺。工具栏有按钮 |
| 打开仓库 | ⌘O | 无 | 缺。成本低，标准键位 |
| 快速切换仓库 | ⌘⇧O | 无 | 缺。应用没有多仓库概念 |

## 建议顺序（待确认）

1. **低风险、不引入新概念**：⌘O 打开仓库、⌘0 跳到 HEAD、⌘⇧F 引用筛选、⌘⇧A / ⌘⇧R 暂存全部 / 取消暂存全部。
2. **中等成本**：⌘← / ⌘→ 导航栈（配合现有的父提交跳转），⌥↑ 父提交。
3. **需要产品决定**：
   - ⌘S 给 Stash 会覆盖「保存」的直觉，是否采用要确认。
   - ⌘P 命令面板工作量大，但它是 Sublime Merge 让所有操作可键盘触达的关键，值得排期。
   - 全部键位终究需要「单一来源」：第 264 轮已把窗口级键位收进 `shortcutTable()`，设置页卡片与键盘分发共用一张表；下一步是让命令面板也读这张表。

## 已知限制

- Sublime Merge 的键位大量按上下文复用（同一个 ↵ 在不同面板做不同事），上表只列了与 SuperGit 现有功能对应的部分。
- SuperGit 的 ⌘C 只在存在差异行选择时注册，输入框里的 ⌘C 保持系统复制。
- 上述 SuperGit 键位均以代码为准；设置窗口的「快捷键」卡片列出同一张表。本文件保留 Sublime Merge 的对照与结论，不再承担「唯一清单」的职责。
