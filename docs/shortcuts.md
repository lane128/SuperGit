# 快捷键对照（SuperGit vs Sublime Merge）

> 目的：把当前 SuperGit 的键位记录下来，和 Sublime Merge 的默认键位逐条对照，决定「取其优势」时先补哪些。
>
> 数据来源：
> - SuperGit：`internal/lobedesk/shortcuts.go` 的 `shortcutTable()` 是窗口级键位的唯一来源（第 264 轮起），设置页「快捷键」卡片直接读这张表；`KeyShortcuts` 与各页搜索框的 `ShortKey` 仍是各控件的本地绑定（2026-11-13 第 160 轮核对，第 182 轮逐条复核）。
> - Sublime Merge：本机 `/Applications/Sublime Merge.app/Contents/MacOS/Packages/Default - Merge.sublime-package` 内的 `Default (OSX).sublime-keymap`，共 113 条绑定，其中大量是按上下文生效的（同一按键在不同面板做不同事）。

### 全局

| 按键 | 动作 |
| --- | --- |
| ⌘1 / ⌘2 / ⌘3 / ⌘4 | 历史 / 分支 / Stash / 工作树 |
| ⌘, | 打开设置窗口（已打开时置于最前） |
| ⌘R | 重新加载仓库 |
| ⌘↵ | 提交 Index（历史页选中工作树行、「提交」标签在前、详情可见，且仓库就绪、无加载或写入任务、无对话框遮挡时） |
| ↑ / ↓ | 当前页列表选择 |
| Home / End | 列表首尾 |
| PageUp / PageDown | 列表翻页（10 行） |
| Esc | 清除差异行选择（历史页的改动与提交详情） |
| ⌘C | 复制选中的差异行（仅在有行选择且焦点不在输入框时） |
| ⇧↑ / ⇧↓ | 扩展差异行选择（历史页的改动与提交详情） |

### 详情区域的焦点导航（Lobe）

这些键由当前获得焦点的控件处理，优先于窗口级列表导航。输入框保留自身的编辑按键。

| 焦点位置 | 按键 | 动作 |
| --- | --- | --- |
| 详情标签栏 | ← / → | 激活上一个 / 下一个标签，首尾循环 |
| 详情标签栏 | Home / End | 激活永久首标签 / 最后一个文件标签 |
| 文件列表 | Tab / Shift+Tab | 整个列表作为一个停靠点；离开列表 / 返回此前聚焦的行 |
| 文件列表 | ← / → | 在文件行、分组标题及行内操作按钮之间移动焦点 |
| 工作区文件行 | Space / Enter | 按聚焦行的原始路径与暂存分组执行暂存或取消暂存 / 外部打开 |
| 文件列表 | ↑ / ↓ | 打开相邻文件标签，并把焦点移至对应文件行 |
| 文件列表 | Home / End | 打开首个 / 最后一个可见文件 |
| 文件列表 | PageUp / PageDown | 按 10 行移动并打开文件 |

关闭当前文件标签后，焦点回到激活的相邻标签；关闭最后一个文件标签后回到「提交」或「摘要」。隐藏详情或打开引用筛选、对话框时不执行后台详情导航。

### 分页

| 按键 | 页面 | 动作 |
| --- | --- | --- |
| ⌘F | 历史 | 聚焦提交搜索 |
| ⌘F | 分支 | 聚焦分支/标签搜索 |
| Space / ⇧↵ | 历史（工作树行） | 暂存/取消暂存选中文件 |
| ↵ | 历史（工作树行） | 用默认应用打开选中文件 |
| ↵ | 分支 | 激活当前可见的选中引用；分支搜索框内也会执行此动作，输入搜索词并非只提交筛选 |
| ↵ | 工作树 | 切换到选中工作树 |

分支搜索先同步可见选择：若此前选中项被筛掉，选择移至当前筛选结果中的第一项；没有匹配项时清空选择。搜索框中的 Enter 随后调用同一引用激活动作。是否改为只提交筛选，仍是 TODO 中的待确认选项。

### 搜索框与选择器的 Esc（2026-11-16 复查）

| 位置 | 当前行为 |
| --- | --- |
| 历史 / 分支搜索框 | Esc 保留查询；连续两次也不清空查询 |
| 检出分支选择器 | Esc 关闭弹窗；重开时查询为空 |
| 引用选择器 | Esc 关闭弹层；关闭时内部 query 可暂存，但每次重开都会清空 |

Esc 优先交给最上层浮层。原生自动化中，引用选择器里的 `needle` 提示先收到一次 Esc，下一次才由引用弹层接收；带键盘焦点的提示不会因移开指针而必然消失。诊断日志按接收控件 ID 确认了该顺序，因此不能把这次“两次 Esc”解释为搜索框的统一规则。

依据：四类实际输入的 UI Tester 观察 `build/lobe-search-escape-typing-observation.log`；普通原生包的四组观察 `build/lobe-search-escape-ybnmusvu/results.json`；隔离依赖副本加分发日志的原生诊断 `build/lobe-search-escape-t7habby4/app.log` 和 `results.json`。日志版只用于诊断，未改项目依赖或普通二进制。移开指针 / 点击输入框来消除提示的后续检查未通过其“无 tooltip”前提，未作为单次 Esc 验收。统一清空查询的 A/B 方案仍待确认。

## 差异清单

| 动作 | Sublime Merge | SuperGit | 结论 |
| --- | --- | --- | --- |
| 搜索提交 | ⌘F | ⌘F | 一致 |
| 搜索分支/标签 | ⌘F（搜索框） | ⌘F | 一致 |
| 提交 | ⌘↵ | ⌘↵ | 一致 |
| 首选项 | ⌘, | ⌘, | 一致 |
| 暂存文件 | ↵ / ⇧↵ | Space / ⇧↵（↵ 留给「打开文件」） | 刻意不同：SuperGit 的 ↵ 是默认动作，Space 更接近文件列表的快速开关 |
| 刷新 | F5 | ⌘R | 键位不同，功能齐全 |
| 切换页面 | ⌘1…⌘4 | ⌘1…⌘4 | 一致（历史页承载工作树行） |
| 命令面板 | ⌘P | 无 | 缺。体量大，需要单独立项 |
| 后退/前进 | ⌘← / ⌘→ | 无 | 缺。可从「父提交」跳转延伸出导航栈 |
| 父/子提交 | ⌥↑ / ⌥↓ | 无（详情里有父提交按钮） | 缺。可先给父提交按钮补键位 |
| 跳到 HEAD | ⌘0 | 无 | 缺。历史页有用，成本低 |
| 引用筛选 | ⌘⇧F | 无（点页头下拉） | 缺。成本低 |
| 文件筛选 | ⌘⌥F | 无（仅从文件历史进入） | 缺。与引用筛选同批 |
| 暂存全部 / 取消暂存全部 | ⌘⇧A / ⌘⇧R | 无（只有按钮） | 缺。成本低 |
| Stash / Pop Stash | ⌘S / ⌘⇧S | 无（Stash 页按钮） | 缺。⌘S 在别处通常表示「保存」，需确认是否占用 |
| 丢弃改动 | ⌫ / ⇧⌫ | 无（右键菜单） | 缺。破坏性操作，键位要谨慎 |
| Pull | F7 / ⌥⌘↓ | 无 | 缺。工具栏有按钮 |
| 打开仓库 | ⌘O | 无 | 缺。成本低，标准键位 |
| 快速切换仓库 | ⌘⇧O | 无 | 缺。应用没有多仓库概念 |

## 建议顺序（待确认）

1. **低风险、不引入新概念**：⌘O 打开仓库、⌘0 跳到 HEAD、⌘⇧F 引用筛选、⌘⇧A / ⌘⇧R 暂存全部 / 取消暂存全部。
2. **中等成本**：⌘← / ⌘→ 导航栈（配合现有的父提交跳转），⌥↑ 父提交。
3. **需要产品决定**：
   - ⌘S 给 Stash 会覆盖「保存」的直觉，是否采用要确认。
   - ⌘P 命令面板工作量大，但它是 Sublime Merge 让所有操作可键盘触达的关键，值得排期。
   - 全部键位终究需要「单一来源」：第 264 轮已把窗口级键位收进 `shortcutTable()`，设置页卡片与键盘分发共用一张表；下一步是让命令面板也读这张表。

## 已知限制

- Sublime Merge 的键位大量按上下文复用（同一个 ↵ 在不同面板做不同事），上表只列了与 SuperGit 现有功能对应的部分。
- SuperGit 的 ⌘C 只在存在差异行选择时注册，输入框里的 ⌘C 保持系统复制。
- 上述 SuperGit 键位均以代码为准；设置窗口的「快捷键」卡片列出同一张表。本文件保留 Sublime Merge 的对照与结论，不再承担「唯一清单」的职责。
