# 快捷键对照（SuperGit vs Sublime Merge）

> 目的：把当前 SuperGit 的键位记录下来，和 Sublime Merge 的默认键位逐条对照，决定「取其优势」时先补哪些。
>
> 数据来源：
> - SuperGit：`internal/lobedesk/shortcuts.go` 的 `shortcutTable()` 是窗口级键位的唯一来源（第 264 轮起），设置页「快捷键」卡片直接读这张表；`KeyShortcuts` 与各页搜索框的 `ShortKey` 仍是各控件的本地绑定（2026-11-13 第 160 轮核对，第 182 轮逐条复核）。
> - Sublime Merge：本机 `/Applications/Sublime Merge.app/Contents/MacOS/Packages/Default - Merge.sublime-package` 内的 `Default (OSX).sublime-keymap`，共 113 条绑定，其中大量是按上下文生效的（同一按键在不同面板做不同事）。

### 详情区域的焦点导航（Lobe）

这些键由当前获得焦点的控件处理，优先于窗口级列表导航。输入框保留自身的编辑按键。

| 焦点位置 | 按键 | 动作 |
| --- | --- | --- |
| 详情标签栏 | ← / → | 激活上一个 / 下一个标签，首尾循环 |
| 详情标签栏 | Home / End | 激活永久首标签 / 最后一个文件标签 |
| 文件列表 | Tab / Shift+Tab | 整个列表作为一个停靠点；离开列表 / 返回此前聚焦的行 |
| 文件列表 | ← / → | 在文件行、分组标题及行内操作按钮之间移动焦点 |
| 工作区文件行 | Space / Enter | 聚焦行属于选区时，对同组所选文件暂存／取消暂存；聚焦行在选区外时仅处理该行。按原始路径与暂存版本校验整组选项；外部打开仍可从文件菜单执行 |
| 工作区文件行 | ⌘A（Windows／Linux：Ctrl+A） | 仅全选当前展开分组，包括滚动屏外行；输入框保留文本全选 |
| 工作区文件标签中的 hunk 标题 | Enter | 仅暂存聚焦片段；已暂存侧取消暂存该片段。输入框、行选区、历史 Diff、加载／读取错误或弹窗期间不执行 |
| 文件列表 | ↑ / ↓ | 打开相邻文件标签，并把焦点移至对应文件行 |
| 文件列表 | Home / End | 打开首个 / 最后一个可见文件 |
| 文件列表 | PageUp / PageDown | 按 10 行移动并打开文件 |

关闭当前文件标签后，焦点回到激活的相邻标签；关闭最后一个文件标签后回到「提交」或「摘要」。隐藏详情或打开引用筛选、对话框时不执行后台详情导航。

工作区文件多选：普通点击单选，⌘／Ctrl 点击同组文件增减选择，Shift 点击选择锚点至目标的连续范围。Modified、Untracked、Staged 三组不混选；同路径的 Index／工作区版本保持独立。右键已选行保留集合并预览该行，右键未选行改为单选。多选菜单显示所选数量，暂存／取消暂存针对所选项；行内图标及菜单中的“此文件”动作仍只处理单文件，所有“全部”按钮仍为全量。同库刷新保留仍存在且未迁组的选择，失效锚点清理；Summary 不因后台刷新切为文件标签。切到 Summary 或已有文件标签不会清空显式选区；底色继续表示选中集合，粗体仅表示当前文件预览。以上手势和边界是 SuperGit 实现选择；Sublime 官方发布记录及本机菜单资源仅确认文件多选和所选暂存／取消暂存能力，未实测这些具体规则完全一致。自动化证据与完整检查状态见 [工作区多选计划](superpowers/plans/2026-11-18-workspace-file-multiselect.md)。

历史提交文件多选：普通点击单选，⌘／Ctrl 点击增减选择，Shift 点击选择锚点至目标的连续范围；键盘打开相邻文件恢复单选。底色表示选中集合，粗体表示当前文件预览；切换 Summary 或已有标签保留集合，取消最后一个选项回到 Summary，再次选择仍可查看补丁。同库同提交刷新保留仍存在的文件，切换仓库或提交清空集合。右键已选行保留集合并预览该行，右键未选行改为单选；复制路径、导出、撤销、文件历史等菜单动作仍只针对右键文件。此处手势复用 SuperGit 工作区规则，尚未完成 Sublime Merge 原生手势一致性验证。实现与检查记录见 [历史文件多选](superpowers/plans/2026-11-18-historical-file-multiselect-scope.md)。

### 搜索框与选择器的 Esc（2026-11-16 复查）

| 位置 | 当前行为 |
| --- | --- |
| 历史 / 分支搜索框 | Esc 保留查询；连续两次也不清空查询 |
| 检出分支选择器 | Esc 关闭弹窗；重开时查询为空 |
| 引用选择器 | Esc 关闭弹层；关闭时内部 query 可暂存，但每次重开都会清空 |

Esc 优先交给最上层浮层。原生自动化中，引用选择器里的 `needle` 提示先收到一次 Esc，下一次才由引用弹层接收；带键盘焦点的提示不会因移开指针而必然消失。诊断日志按接收控件 ID 确认了该顺序，因此不能把这次“两次 Esc”解释为搜索框的统一规则。

依据：四类实际输入的 UI Tester 观察 `build/lobe-search-escape-typing-observation.log`；普通原生包的四组观察 `build/lobe-search-escape-ybnmusvu/results.json`；隔离依赖副本加分发日志的原生诊断 `build/lobe-search-escape-t7habby4/app.log` 和 `results.json`。日志版只用于诊断，未改项目依赖或普通二进制。移开指针 / 点击输入框来消除提示的后续检查未通过其“无 tooltip”前提，未作为单次 Esc 验收。统一清空查询的 A/B 方案仍待确认。
