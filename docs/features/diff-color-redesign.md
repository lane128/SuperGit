## 候选探索记录（实施范围以上面的已批准补充为准）

以下保留初次方案比较的目标、限制和审查证据；其中“不修改产品／尚未授权／待选择”描述的是设计阶段状态。

## 目标与约束

用户反馈：“现在的 diff 对比太不明显了，日夜间都是”，要求参考常见 CLI diff，提供多套日间／夜间配色。成功标准是先看出哪块新增／删除，再连续读清代码；选中和搜索时仍能辨认增删。

- 本轮不修改 Go、依赖、Git 写入、偏好、安装包，不提交或发布。
- 每套同时提供浅色与深色，内容、字号、行高一致，避免只比较漂亮截图。
- 不新增产品配色选择器；预览控件只用于选方案。最终是否做成设置需另行授权。
- 保持现有工作区、历史提交、overview、revision comparison、统一／左右 diff 的内容与操作语义。视觉静态符号不进入复制文本或 patch，不占用暂存点击目标。
- 不引入语法高亮。词内差异高亮当前不存在，仅作为明确标记、默认关闭的扩展预览，不属于默认实施范围。

## 现状调查

- `workspace.go:703`、`history.go:1651`、`overview_lines.go:108` 各自绘制增删背景，新增为 `Success.Alpha(0.075)`，删除为 `Error.Alpha(0.065)`。相对底色变化很小，不能只提高正文对比度来解决色块难辨认。
- `workspace.go:982` 的 `lineTextColor` 将新增用普通正文色、删除用次级正文色，删除内容比上下文更弱。
- 工作区／历史选中态再叠加蓝色（0.16，活动行 0.24）；overview 使用 0.16。选中可削弱原增删色相。
- `diff_find.go:240` 使用 RichText 做搜索命中；已有 warning 高亮／当前命中下划线，但没有词级增删差异算法。
- `revision_compare.go:276` 直接绘制文本并使用 `lineTextColor`，没有完整行底色与 gutter，未来实施不能只改 workspace 的颜色就宣称所有入口一致。
- 默认 SuperGit 正文底色日间 `#FFFFFF`、夜间 `#161B22`。本稿沿用它们，使 diff 自己更醒目，不重设计整个应用。

## 参考来源

- [Git diff.c](https://github.com/git/git/blob/master/diff.c)：默认 old 红、new 绿、frag 青、context 普通、meta 粗体。实际 ANSI 红绿随终端主题变化；不把某一组 RGB 说成 Git 的统一官方色。
- [delta 完整参数](https://dandavison.github.io/delta/full---help-output.html)：区分 minus/plus、emph/non-emph、syntax-theme，以及 light/dark；`keep-plus-minus-markers` 默认 false，开关用于保留 Git 的 ＋／−。
- [delta 自定义主题](https://dandavison.github.io/delta/custom-themes.html)：syntax-theme 控制文字高亮；整行底色和装饰属于另一层配置。

这些是表达方式参考。下面所有色值是本次定制候选，不是复制某个 CLI 的官方主题，也没有把 delta 的语法解析能力算进配色改动。

## 四套候选

所有方案都有整行底色、语义文字、增删符号栏、hunk、选中和搜索层。

| 方案 | 主张 | 日间：新增底／字；删除底／字 | 夜间：新增底／字；删除底／字 | 取舍 |
| --- | --- | --- | --- | --- |
| A Git 经典 | 用红绿字色辨认，轻底色辅助；最小视觉改动 | `#EAF6ED` / `#14552C`；`#FCECEB` / `#8A2030` | `#182B20` / `#97E5A8`；`#342023` / `#FFA6AA` | 贴近 CLI；连续彩色代码较多，色块辨识弱于 B/C |
| B Delta 层次（推荐） | 语义行底＋高对比正文，层次分明 | `#D9EFDF` / `#173C26`；`#F8DCE0` / `#59242C` | `#203E2C` / `#D9F5E1`；`#4A2830` / `#FFE1E5` | 比现状明显，长时间阅读平衡；适合统一 diff token 架构 |
| C 鲜明红绿 | 较浓底色＋鲜明文字，优先扫读 | `#C7EBD1` / `#103E23`；`#F7CBD0` / `#641A2B` | `#204F35` / `#C6FFD6`；`#602C3A` / `#FFE1E8` | 最醒目，大片修改时视觉重量更高 |
| D 蓝橙区分 | 新增蓝、删除橙，探索非红绿方向 | `#D9EAFA` / `#153D63`；`#F6E1C8` / `#633B13` | `#203D59` / `#D7EDFF`；`#4B3723` / `#FFE6C7` | 可减轻仅依赖红绿辨色的问题，需适应新语义；不宣称色觉认证 |

建议先对比 B 与 C：B 适合日常持续阅读，C 更强调快速找到变更。A 保留熟悉的 CLI 字色风格，D 给出不同色相的替代方案。四套候选的实现复杂度接近，选色不要求加入新设置；词内差异另算。

## 共同状态设计

- 保留 ＋／− 与行号，单色阅读仍有语义线索。符号栏带 3 px 语义侧线；它是展示元素，不成为第二个暂存按钮。
- 新增／删除代码与背景目标 ≥7:1；行号和符号 ≥4.5:1。颜色标记至少 3:1；正文不能靠降低透明度退居次要。
- 选中：保留原行底色，用 2 px 内框＋gutter 左侧指示条。日间 `#075CCA`，夜间 `#9CCAFF`。不再用整行蓝覆盖增删底色；活动行／多选边界／键盘焦点仍需在原生设计细化中区别，并保留现有选中模型。
- hover：轻边线，不换增删底；原生实现仍保留行尾暂存动作。预览的行点击只是同步展示选中，不能视为真实 App 点击行为。
- hunk：日间 `#E5EEF8` / `#254C70`；夜间 `#25364A` / `#A8D2FF`。与正文区分，但不抢增删语义。
- 搜索：黄色底＋下划线，日间 `#FFE08A` / `#352600`；夜间 `#FFD26A` / `#2A210C`。预览展示活动命中样式；真实实现还需保留普通匹配与活动匹配区别。搜索高于词内强调，整行增删底仍可见。
- 无内容的左右占位用中性底，不能伪装成删除。空行仍显示符号与整行色块。长行在代码面板内横向滚动，不撑破页面。
- 词内强调（仅扩展预览）：同色系更强的小背景，默认关闭。若选中实施，需要差异配对／字素边界算法、性能预算、搜索与文本选择优先级、复制语义测试；本轮不承诺这项能力。

## 预览内容与验证

`design/diff-color-variants.html` 提供 4 方案 × 2 模式，同时展示日夜。可切换统一／左右、Go／配置中文／空白边界、13/15/17 px 字号、420/320 px 窄容器、行选中、搜索、可选词内强调、当前主题近似对照。预览使用内置 JetBrains Mono Regular，与产品代码字体来源一致；系统对中文可发生字体回退。

现状对照仅近似默认 SuperGit 增删字色／透明行底／蓝色选中，不是像素级原生复刻；hunk、行号布局和预览控制不用于评估旧版布局。

检查脚本：`build/check-diff-color-design.cjs`。结果：

- 72 组布局配置：1500/900/400 viewport × 统一/左右 × 3 内容场景 × 13/17 字号 × 词内强调开关。
- 每组同时含现状与 4 候选的日夜面板；无页面级横向溢出、选中与搜索节点正常。逐行用 DOM Range 断言文字右边界不超出行底色／选中框范围，覆盖长新增／删除行。
- 8 候选模式、96 次对比度断言；正文最低 7.63:1，符号／行号、hunk、扩展词内文字和选中框满足各自阈值。
- 方案单独查看／返回、Space/Enter 同步切换选中通过；无 JavaScript 异常。
- 已查看四套全览、B 词内＋搜索、B 左右截图；左右模式自适应时日夜上下排，让每个面板有足够代码宽度。
- 对比度数值衡量文字／底色可读性，不等于增删色块一定容易分辨；后者需用户目视选择与原生实测。

证据：`build/diff-color-design/{results,contrast}.json`、`all-light-dark.png`、`b-emphasis-search.png`、`b-split.png`、`phone-400.png`。设计 HTML 与证据均为本地忽略文件。本轮没有产品代码变更，未跑 Go 测试或构建 App。

## 选定后的实施计划（尚未授权）

0. 配色选择与实施批准分开：实施批准前先细化并评审活动行、非活动选中行、多选边界、键盘焦点、普通／活动搜索匹配、文本拖选的组合。这些状态未在当前比较稿完整模拟，不得以本轮通过代替验收。
1. 提取局部 diff token/helper，日夜显式映射；不要更改全局 Success/Error 而影响状态徽章、按钮、通知等其他区域。
2. 接入 workspace、history、overview 的重复颜色路径，并补齐 revision compare 的背景处理。统一／左右模式共享同一套色值。
3. 更新仍要求“删除等于 TextSecondary”的旧测试，增加所有支持 UI palette × 日夜 × 普通/hover/选中/搜索测试。明确固定 diff palette 在 Catppuccin 中的边界与邻接背景，不能只验证默认主题。
4. 保留行选择、文本选择、复制、gutter 暂存、虚拟滚动、搜索定位行为。新增静态符号不得复制到原始内容或改变 patch 字节。
5. 按 T3 完成测试与独立审查后 `make app`；在隔离仓库中验证多入口、日夜、大小字号、窄窗口，记录截图。人工验收后再安装/提交，授权另计。
