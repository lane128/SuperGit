# 历史提交 Summary：元数据布局预览

状态：先在原工作台 HTML 场景「5. 历史提交详情」完成设计，确认后落地到原生 Summary。显示修改保留在本地，未提交。

- **Hash**：与 Author 共用标题列；值使用代码字体，复制按钮紧随值。栏宽不足时省略显示，鼠标悬停可读完整值，复制读取完整值。
- **Author**：按 `Name<Email>` 显示，可在 `<` 前换行；无邮箱时不补造示例地址。
- **Date**：时间从作者行最右端移到其下方独立一行，与 Hash、Author 的值左对齐。保留提交的原日期与时间，不转成相对时间。
- **验收**：比较宽／窄详情栏、浅／深主题；切换不同历史提交检查各值跟随当前提交。保留父提交跳转和既有引用信息。

## 浏览器验证

## 行距修正设计

900 × 700 原生窗口复现了截图：哈希→作者、作者→日期、日期→父提交的中心距离分别为 26.48、20.96、28.98 pt。原布局给每行相同的外部间距，但行本身由不同高度的控件撑开。

让元数据独立成组：单行最小高度容纳父提交按钮（默认 29 pt）和复制图标（24 pt），组内留 2 pt，默认中心步长 31 pt。保留正文到元数据组的原有距离。作者和多父提交内容换行时允许所在行自然增高；可选签名沿用原有显示条件。验收以四个单行标签实际中心步长误差不超过 1 pt 为准，不缩小按钮点击区域。

复测：同一 900 × 700 原生测试窗口中，三段中心距均为 **31.00 pt**，哈希与复制按钮间距仍为 4 pt。[修正后截图](../../build/lobe-narrow-window-xnbmc0pn/07-summary-metadata.png) · [实际测量值](../../build/lobe-narrow-window-xnbmc0pn/results.json)。

## 父提交链接 · HTML 预览

父提交短 SHA 改为带下划线的等宽文本链接，无按钮底色、边框或内边距。每个父提交分别可点击或 Tab 聚焦后按 Enter 跳转。普通提交显示一个链接，合并提交按 Git 父序并列，根提交不显示父提交行。保留 Hash 行的复制按钮，以及单行元数据 29 + 2 的纵向节奏。预览确认后，原生 Summary 同步使用可聚焦的文本链接：展示短 SHA，按完整 SHA 在应用内导航，历史返回行为保留。Stash 的索引和未跟踪文件快照仍为只读文本。

900 × 700 原生窗口中，分别用鼠标点击和键盘 Enter 打开合并提交的两个父提交，目标与 Git 记录的完整 SHA 一致，浏览前后仓库状态不变；四行中心距仍为 31 / 31 / 31 pt。[父提交链接实机截图](../../build/lobe-narrow-window-yswji43l/07-summary-metadata.png) · [验收记录](../../build/lobe-narrow-window-yswji43l/results.json)。
