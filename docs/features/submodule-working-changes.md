# 子模块工作区改动

Status: Implemented; native acceptance passed

Acceptance: [子模块工作区改动验收](../acceptance/2026-11-23/submodule-working-changes.md)

Date: 2026-11-23

Related: `0fedcfe`

## 背景和目标

SuperGit 用 `git status --porcelain=v2 --ignore-submodules=none` 读取父仓库。子模块 HEAD 和父仓库暂存区的 gitlink 相同，只改动子模块里的已跟踪和未跟踪文件时，Git 仍可能返回 `.M S.MU`。当前界面把 `.M` 直接分进父仓库的 Modified Files，父仓库的改动总数也随之增加。

临时仓库复现了该记录。把子模块中的改动从两个文件增到三个时，父仓库的记录完全相同。提交其中一个文件使子模块 HEAD 移动后，父仓库记录变为 `.M SCMU`。将新 gitlink 暂存到父仓库后，只剩子模块内部改动时，记录为 `MM S.MU`，其中第一个 `M` 表示父仓库确实有已暂存的指针改动。

## 可见行为

| 场景 | 父仓库工作区 | 父仓库侧栏的子模块行 |
| --- | --- | --- |
| 子模块 HEAD 与父仓库暂存区一致，子模块有一个已修改文件和一个未跟踪文件 | Files、改动总数和提交面板只反映父仓库自己的改动 | 分支名或短 hash 右侧显示 `2` |
| 子模块 HEAD 移动，子模块还有两个本地文件改动 | Modified Files 显示一条待暂存的 gitlink 改动 | 仍显示 `2`，按该子模块中实际待提交的文件数计算 |
| 父仓库已暂存 gitlink，子模块 HEAD 与暂存区一致 | 该 gitlink 只出现在 Staged Files | 子模块有本地改动时继续显示数量 |
| 子模块干净 | 父仓库根据 gitlink 的实际状态显示 | 保留分支名或短 hash |

每个路径计一次。同一个文件既已暂存又有未暂存内容时计 `1`，已暂存删除、随后同名重建为未跟踪文件时也计 `1`。工作区总数和徽标共用这套计数规则，各 Files 分组仍显示各自的版本。计数包含未跟踪文件和冲突文件，遵循 Git 的忽略规则。直接子模块行的数量与打开该子模块后的 Files 总数一致。嵌套子模块内部文件的数量在其直接父仓库的对应行展示。

点击子模块行沿用现有打开操作。完整分支名或 hash 与本地改动数一并进入提示和辅助功能描述。计数徽标使用现有浅色和深色主题的强调色，在窄窗中优先保留计数和子模块路径尾部。干净、未初始化或状态读取失败的子模块不显示数量。

## 实现方式

- `internal/gitrepo` 保留完整的 porcelain 状态和 `Submodule.Dirty` 语义，用于脏检查、冲突、暂存及更新校验。增加共享的工作区展示规则，只有在工作树的 `M` 来自子模块内部修改或未跟踪标记，且没有 gitlink 提交变化时，才从展示层省略该未暂存版本。暂存版本独立显示，删除、类型变化、重命名和冲突保留。使用原始状态条目校验文件操作，真实 gitlink 改动继续支持已有操作。
- `internal/lobedesk` 在工作区共用这套展示规则。Files、提交面板、历史改动数、图表、工作区总览、仓库标签的改动圆点和文件版本切换使用一致的口径。侧栏从已有 `Submodules` 读取得到每个子模块的本地文件数，并在 ref 旁渲染徽标。
- 文件面板的批量操作以对应版本的可见条目选目标。只有子模块内部改动时，父仓库的 Stage All、Stage Tracked 和 Discard All 仍能处理各自范围内的普通文件。真实的可暂存 gitlink 改动继续支持暂存和取消暂存。可见的未暂存 gitlink 阻止 Discard All，冲突继续阻止批量操作，沿用现有受保护文件提示。将原始条目携带到执行阶段重新验证，丢弃只接收显式的父仓库文件路径，操作发现目标变化时沿用现有拒绝行为。单个文件、子模块更新、stash 和其他写入保护继续使用原始状态。
- 自动刷新沿用现有的本地状态轮询与标签切换校验。父仓库 porcelain 通常能发现干净到有改动的转换，改动数来自子模块自身的状态。打开或刷新时复用已有子模块读取，为实际展示的每个已初始化子模块保存计数或未知状态。活动轮询和标签切回均优先复查父仓库报告内部改动的子模块，以及上次已有计数或读取失败的子模块。后一组能覆盖父仓库先读到干净、快照随后读到子模块变化、子模块又在下一次轮询前恢复干净的时序。
- 父仓库的脏标记受嵌套仓库配置影响。三层临时仓库中已验证 `ignore=all` 能让最外层状态为空，而直接子模块有一条嵌套 gitlink 改动。对其余已初始化子模块做小批轮查。每轮限制额外探测数量及总耗时，按批内轮转避免某个子模块阻塞后续项，并与父仓库状态探测分别计时。父仓库状态已变化即可进入现有刷新流程。只读子模块计数失败时，父仓库快照照常显示，该徽标省略并在子模块恢复可读后刷新。单次探测超时留给后续轮次重试。若父仓库自身的 `git status` 失败，沿用现有加载失败与重试提示，依赖最新状态的操作沿原有规则拒绝执行。
- 改动限定在默认 macOS 工作台的工作区展示、子模块计数及其观察。应用设置、发布流程和 Git 写操作的语义不在本次范围内。侧栏沿用现有布局，不需要单独的 HTML 预览。

## 取舍

直接给全部 `Status` 调用改用 `--ignore-submodules=dirty` 会让原始状态失去内部脏标记。父仓库的展示规则只处理可见的工作区版本，现有写操作读取的状态还能用于安全检查，轮询也能据此定位需要观察的子模块。

## 验证

- 用真实 Git 临时仓库覆盖 `.M S.MU`、`.M SCMU`、`MM S.MU`、子模块恢复干净、父仓库普通改动，以及真实 gitlink 删除或类型变化。测试批量暂存和丢弃只处理对应版本的可见父仓库文件、真实 gitlink 仍可暂存、gitlink 和冲突的丢弃保护，以及执行时重新验证失败的情况。
- 测试侧栏的已修改、未跟踪、同时已暂存和未暂存、暂存删除后同名重建等文件计数。验证总数与各分组及文件版本切换一致，并检查长 ref、窄侧栏和辅助功能描述。
- 测试父仓库 porcelain 保持相同时子模块计数 `2 → 3 → 0` 的活动轮询和标签切回，分别覆盖父仓库早于子模块读取的时序、嵌套 Git 配置使外层状态保持干净、计数读取失败恢复、个别探测超时和父仓库 `git status` 自身失败。
- 用 `make check` 和覆盖率检查验证跨包行为，并在验收前完成独立代码审查。

## 原生验收

1. 用本地 Git 仓库作为子模块源。源仓库提交两个已跟踪文件，父仓库提交自己的文件和 `modules/child` 的 gitlink。用 `make app` 启动 `build/SuperGit.app` 打开测试目录，另用 `make e2e-build` 和现有自动化驱动记录文件列表与截图。
2. 修改父仓库文件。在子模块修改一个已跟踪文件并新建一个未跟踪文件。打开父仓库 Submodules 组，检查父仓库 Files 只有父文件，子模块行的 ref 旁显示 `2`，打开子模块看到两个文件。
3. 回到父仓库，在磁盘上修改子模块的另一个已跟踪文件，观察徽标变成 `3`。将测试仓库中这三项子模块改动逐一清理，徽标消失。对离开后再切回的仓库标签复查计数。
4. 在子模块创建新提交并切到 detached HEAD，再新增本地文件。父仓库 Modified Files 显示一条 gitlink，侧栏显示短 hash 和本地改动数。暂存 gitlink 后检查它只在 Staged Files，子模块里的文件仍在。
5. 在三层仓库中改动最内层子模块的普通文件，核对其直接父仓库的子模块徽标。复现嵌套 `ignore=all` 下最外层 porcelain 为空的情况，确认中间仓库的实际 gitlink 改动仍能更新最外层徽标。
6. 浅色宽窗和深色窄窗都检查计数位置、长 ref 截断、路径尾部及完整提示。验收结果记录在 `docs/acceptance/2026-11-23/`。

## 风险和回滚

父仓库文件列表、计数与文件所选版本应同时采用展示规则。原始状态用于写操作的目标检查，以防把掌握的子模块脏信息丢掉。通过状态和计数分别验证，确保新增轮询优先检查有内部改动的子模块，其余已初始化模块只做有上限的小批轮查。回滚使用 `git revert`，无需迁移数据。
