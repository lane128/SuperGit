## Background and goal

用户反馈：设置窗口仍有大面积留白，要求各个 tab 重新设计，先审核设计。使用者是日常通过 SuperGit 调整外观、历史展示、Git 偏好与查看快捷键的桌面用户。

截图问题来自两层布局：设置窗口允许无限拉宽并通过 `StateKey: "settings"` 恢复旧尺寸；640 DIP 的详情卡片又在整个剩余区域内居中。窗口扩大时，导航到表单的距离随之增加。卡片内还有重复标题、统一大底板和混合风格的按钮。此前测试只证明内容没有越界，没有检验导航与内容的距离以及窗口放大后的整体比例。

目标：五个页面有一致的信息层级；导航到正文的距离恒定；表单宽度可读且紧凑；大字号和窄窗口仍能使用；现有设置、快捷键、更新及保存语义完整保留。

## Non-goals

- 本轮仅设计与审核，不修改 Go / Python 产品与验收代码，不安装、commit、push 或发布。
- 不重设计主工作台的仓库 tab、文件 tab、提交页；当前截图范围是 Settings 内五个分类及其页内分段控件。
- 不新增设置搜索、快捷键编辑、自定义快捷键、设置导入导出、额外开关或确认保存按钮。
- 不改变 Git 操作、后台 fetch 时机、更新签名/安装流程、权限或设置格式。
- 上一轮移除主侧栏 History 的修改及其他未提交文件保留。

## Approach

直接打开 [交互设计稿](../../design/settings-redesign.html)。它是本地 HTML，五个分类可切换，支持中英文、浅深色、普通/大字号和窗口尺寸预览。顶部审核工具栏属于设计稿，不属于产品。所有示例数据和更新状态均明确作为设计预览，不读写实际设置，不调用 Git 或更新服务。

### 推荐方向：有边界的偏好设置窗口

**这是待用户批准的窗口行为变更，尚未实施。**

- 默认 848×680 DIP；最小保留 560×480；最大宽度 848，最大高度建议 860。允许窄化与纵向调整。
- 设置窗口禁用全屏及最大化。主工作台窗口行为不变。理由是固定阅读宽度的偏好设置不需要占满超宽显示器。
- 左导航固定 160 DIP；右侧水平 padding 24 DIP；正文在默认尺寸下宽 640 DIP。计算：160 + 24 + 640 + 24 = 848。
- 正文从导航右侧 24 DIP 处开始，不使用居中容器。宽度公式 `min(640, viewportWidth - 160 - 48)`；内容可用宽度不足 480 时（窗口宽度小于 688 DIP），标签与控件改为上下排；布局回归覆盖 687/688 DIP 阈值两侧。
- 只在右侧正文滚动，导航不跟随正文滚动；每个 tab 保留自己的滚动位置。分类切换不改变窗口尺寸。
- 小于桌面最低尺寸的 HTML 浏览器预览允许导航横排，这是审核页的阅读适配，不代表新增手机产品。
- 不通过拉高短页面、增加无用介绍或放大控件来填满所有空白。Git/About 的下方允许自然剩余空间；重点消除横向断裂、表单内无意义的大块底色。

### 已保存尺寸与可行性

已核对 `third_party/mygo/window.go`：支持 `MaxWidth`、`MaxHeight`、`DisableMaximize`、`DisableFullScreen`。`window_state.go` 会恢复旧的宽高、最大化与全屏状态；不能假定只改 WindowOptions 就能覆盖旧状态。

推荐使用新的**仅窗口几何**键 `settings-compact-v1`，首次进入新布局时按推荐尺寸打开。旧 `settings` 几何记录原样保留，不删除其他窗口状态，不改用户偏好设置文件格式。之后在新键内记住允许范围内的位置/尺寸。实现前必须测试平台对 MaxSize、最大化/全屏限制及多显示器工作区的实际处理；如果不能满足，只报告阻塞，不静默修改 vendored MyGo 或换用全局窗口策略。

该方案明确牺牲旧设置窗口的位置/尺寸连续性；外观、字体、语言、Git、更新偏好都必须保留。审核需确认这项取舍。

### 视觉与组件规范

- 沿用应用主题 token，不固定成截图的某个配色；浅深色同等实现，验收包含 SuperGit 与 Catppuccin Macchiato。
- 参考浅色：BgContainer `#FFFFFF`、BgLayout `#F3F4F6`、Text `#1F2328`、TextSecondary `#59636E`、BorderSecondary `#D8DEE5`、Primary `#0969DA`。深色从现有 palette token 映射，不直接反转颜色。
- 系统 UI 字体承载标签和正文；代码/快捷键使用现有代码字体。标题 20/600，分组标题 12/600，表单文字 13，说明 12；遵守现有字号缩放。
- 间距使用 4/8/12/16/24；导航项默认高 36、左右内边距 12、相邻间隔 4；选中项轻底色+加粗，与键盘焦点环分别表达。
- 页面标题不再重复包在大卡片内。分组以标题和细分隔线表达，只有同一表单组共享浅边框/8px 圆角，不加阴影；预览独立使用较淡底色。
- 表单行默认至少 44 DIP，label 在左、控件在右；说明放在所属行下方。长说明换行，行高随文字增长。窄模式上下排时控件左对齐。
- 分段控件是一条连续轨道，选中项为一个平整的 thumb；未选项无各自边框和阴影。各选项同组等宽，常见三项在默认宽度/1.15 字号下保持单行。窄模式整组移到标签下一行；不切成不规则的多行按钮。
- 多选项继续使用 checkbox，不改成看起来互斥的分段控件；下拉仍用菜单触发器。
- hover、pressed、focus、selected、disabled 区分；selected 与 focus 可同时存在；禁用原因以可读说明保留，不仅降低透明度。
- 分类使用 RoleTabList / RoleTab；上下方向键只移动焦点，Enter/Space 激活；Tab 进入正文。选择项、焦点与已保存的滚动位置保持独立。切换页面关闭遗留菜单，沿用现有实现。
- 没有自动播放动画；仅保留必要的短颜色反馈，尊重减少动态效果。

### 五个页面

| Tab | 分组与内容 | 关键规则 |
| --- | --- | --- |
| 外观 / Appearance | 界面：主题、配色、语言；字体：界面字体/字号、代码字体/字号/跟随；阅读预览 | 删除页末大段总说明，将语义分别放回所属行；字体预览保留，使用短例子，不拉长整个表单；代码字号仍是原来的范围与步进 |
| 历史 / History | 提交列表：作者、提交时间；历史线图：显示图、线宽、节点大小；提交详情：提交信息、文件列表、补丁 | 不因显示设置触发 Git 写入；Summary 与 patch 至少保留一个，禁用项解释原因为何；不新增图预览或新开关 |
| Git | 后台获取：自动获取、清理过期远端引用、获取频率 | 自动获取关闭时 prune 不可操作且解释原因；频率五档保持原值，特别是 0 的实际语义“只在打开时”不能误写成完全禁止 fetch；修改频率不立即执行 fetch |
| 快捷键 / Shortcuts | 完整快捷键表，按现有 shortcutGroupOrder 分组；动作在左、键帽在右 | 只读；生产版必须来自 shortcutTable() 及其追加项，不维护第二份表；HTML 展示代表性条目并标明节选；长动作名称换行，不裁掉键位；不新增搜索框 |
| 关于 / About | 产品名、真实构建版本、设置路径；软件更新偏好和状态/动作；独立恢复默认设置区 | 不伪造“已是最新”；idle/checking/upToDate/available/downloading/verifying/readyToRestart/error 沿用状态机；下载取消、查看详情、重启安装等既有动作保留；恢复默认仍有确认且保留语言 |

### 状态与反馈

- 自动保存继续即时应用。保存失败保留当前会话值、显示设置窗口内的持久警告，不声称已保存，不影响主窗口。
- 错误详情、更新详情和确认对话框仍归属触发它们的 Settings 窗口。重设计只替换布局与展示。
- 原生菜单、文本选择、焦点顺序、更新提示点、Code font follow 的禁用规则保留。
- 关于页的更新状态需要分别绘制文字+动作，不仅换一个颜色；HTML 的审核工具可选择代表状态以审核布局。
- 重置确认文案明确范围是应用偏好，不是仓库数据。关闭或取消不写配置；确认后沿用现有重置处理。

### About 状态保留矩阵

以 `update.go: updatesCard / updateSettingsStatusText` 为依据。每一行都必须验证文字、可用动作与动作归属；不以仅验收代表状态替代全矩阵。

| 状态 | 文字 | 动作 |
| --- | --- | --- |
| idle | 尚未检查更新 | 检查更新 |
| checking | 正在检查更新 | 检查中按钮禁用 |
| upToDate | 当前版本已是最新 | 检查更新 |
| available | 有可用更新＋真实版本 | 查看详情（主）、检查更新 |
| downloading，TotalBytes > 0 | 下载版本＋百分比（上限 100%） | 查看详情（主）、取消下载 |
| downloading，TotalBytes <= 0 | 正在下载＋版本，不展示虚假百分比 | 查看详情（主）、取消下载 |
| verifying | 正在校验＋版本 | 查看详情（主） |
| readyToRestart | 就绪＋版本 | 重启并安装（主）、查看详情 |
| error | 错误说明，长文本换行 | 检查更新 |

所有状态在 `LastCheckedAt` 非零时显示本地时间 `YYYY-MM-DD HH:mm`，为零则不显示。HTML 固定日期和版本只作布局示例；原生验收同时覆盖零值/非零值、长版本和长错误。更新提示点沿用现有规则。

## Alternatives and trade-offs

| 方案 | 好处 | 问题 / 结论 |
| --- | --- | --- |
| 推荐：限制设置窗口宽度，紧凑表单 | 从根源消除截图的大面积横向空白；保留固定阅读宽度；所有 tab 一致 | 改变设置窗口最大化/全屏与旧几何恢复行为，必须明确审核 |
| 任意宽窗口，正文靠左、宽度固定 | 改动窗口行为较少；导航到内容距离恒定 | 只是把空白移到右侧，不能完整回应用户反馈 |
| 任意宽窗口，表单铺满/多列 | 利用超宽窗口 | 标签与值距离变大，短页面仍稀疏；与用户此前要求固定详情宽度冲突；五个 tab 数据量差异很大 |
| 按页面自动缩放窗口 | About/Git 更紧凑 | 切 tab 时窗口跳动、阅读位置不稳定，不采用 |

## Impact

- Modules / files（批准后才改）：`settings_window.go`（尺寸与几何键）、`settings_navigation.go`（分类样式）、`settings_page.go`（分组、表单与分段控件）、`code_font.go`（既有字体行适配）、`update.go` 的 `updatesCard` 展示层、必要 i18n 文案；对应布局/导航/保存失败/禁用原因/重置/更新测试及 `native-lobe-settings-layout-smoke.py`。
- Compatibility：保持五个 section key；保留可恢复滚动状态；无设置 schema 变化。旧窗口几何不删除但不再沿用；主窗口几何键不变。
- Data / update signing / permissions：不变。可视化重排不触碰更新下载、签名校验、安装和 Git 执行实现。
- 设计稿只记录真实现有功能。审核工具栏中的尺寸、字号、主题、状态模拟控件不是新增产品设置。

## Test plan

- Unit tests：中英文 × 两主题 × 1.0/1.15 字号，五页全部覆盖；逐项检查控件可达、无横向溢出、选中项与 keyboard focus、tab 切换与滚动恢复。
- Regression tests：宽布局下正文起点恒等于导航右边界+24 DIP；默认详情 640 DIP；分段控件默认不换行，窄布局整组移到下一行；小窗口所有选项、长路径与更新错误仍可读。
- 窗口几何：模拟旧 `settings` 宽度 1600、Maximized/FullScreen=true 的已保存状态；新设置窗口首次用 848×680 打开，保留旧记录和所有偏好；新几何按新键保存；重复开关不重置合法尺寸；主窗口不受影响。
- 行为保护：保存失败驻留与恢复、language 保留、禁用原因、最后一个详情区不可取消、fetch interval 不立即触发、checkbox 偏好持久化和 About 全状态动作映射。
- 快捷键：最终页面条目与 shortcutTable() 完全一致，包含函数末尾追加的导航/命令/文件 tab 等绑定；不要仅验证设计稿的节选。
- e2e / automation：`make app` 实际 bundle，隔离配置与仓库。848×680、560×480，以及在 1600/2000 DIP 桌面上尝试拉宽/最大化；检查真实窗口几何、边距、两侧边界和滚动，而不是只检查 Go 常量。
- T3 验证用一次 `go test -cover ./...`、`go vet ./...`；窗口平台或共享底层确需改变时升级为 `make check` 并重新审核范围。
- 本轮未覆盖：HTML 不证明 MyGo 的布局、原生窗口约束、保存或更新行为；这些都是批准实施后的原生验收项。

### 可复现的原生验收 fixture（批准后实现）

当前 `scripts/native-lobe-settings-layout-smoke.py` 已使用 Python `TemporaryDirectory`、独立 Git 仓库和子进程环境 `HOME`。实施时在该脚本增加 `--redesign` 场景；这是待实现的入口，目前不可当成已通过的命令：

```sh
make app
make lobe-e2e-build
python3 scripts/native-lobe-settings-layout-smoke.py --redesign
python3 scripts/native-lobe-settings-layout-smoke.py --persistence
```

`--redesign` 必须实现以下步骤，并把解析后的路径、fixture、构建参数和结果写进本次 `build/` 证据目录：

1. 每个 case 建立新的临时 `root/home` 和 `root/repo`。通过 Python `subprocess.Popen(env=...)` 只给验收进程设置 `HOME=root/home`；偏好路径为 `root/home/Library/Application Support/supergit/settings.json`。隔离 Git 全局配置，关闭自动 fetch、自动检查/下载更新。`SUPERGIT_TEST_CONFIG_DIR` 只覆盖偏好目录，不能独自承担窗口几何隔离。
2. MyGo 默认几何位于 `os.UserConfigDir()/App.Name()/window-state.json`，与上述偏好路径分开。验收构建记录 `App.Path(PathUserData)` 的实际解析结果；启动任何带 `StateKey` 的窗口前断言两个实际路径均位于本 case 的 `root/home`，否则立即退出。不要仅猜测 App.Name 的大小写，也不修改用户真实几何文件。
3. 在解析出的几何文件写入如下 fixture（真实主窗口若未使用 StateKey，保留一个无关 sentinel 以测试 store 兼容性，并另验主窗口行为）：

   ```json
   {"settings":{"x":80,"y":80,"width":1600,"height":900,"maximized":true},"unrelated-fixture":{"x":100,"y":100,"width":900,"height":600}}
   ```

   分别重跑普通超宽、`maximized:true`、`fullScreen:true` 三个 case，不把两个系统状态同时置真作为唯一用例。旧 `settings`、sentinel 和偏好必须保持；新 `settings-compact-v1` 首次不受旧值影响，关闭后出现新记录。再把新窗口缩到 700×600，关闭/重开确认合法尺寸保留。
4. 默认 `make app` bundle 做真实布局与窗口尺寸验收；自动化版和确定性状态版放进本次临时目录。状态版只通过 Go `-overlay` 替换设置页读取的 `updater.Snapshot`，为上表每行提供固定 State、Release.Version、LastCheckedAt、DownloadedBytes、TotalBytes、Error；注入记录动作的测试接收器，禁止访问公网和执行安装。源码覆盖与接收器均只在测试构建中生效，不增加产品开关，不改 vendor。证据必须区分“真实 bundle 的窗口/布局”与“注入快照的展示/动作映射”，不能把后者当成实际更新服务通过。
5. 保存失败复用当前 `--persistence` 的确定性步骤：仅把临时 `settings.json` 改名备份，再在同名位置创建目录，触发保存；确认会话值保留和旧文件字节未变。移除本次生成的目录、恢复备份，再保存验证警告消失。reset 只对临时偏好执行，前后对比仓库 HEAD、refs、index、status、文件字节。
6. 多显示器：在外接显示器上保存新几何，关闭验收进程，断开显示器并重启；再在较短工作区重复。预期标题栏、分类导航可见可操作，正文末尾动作通过滚动可达。若没有对应硬件，标明“未实测”，用 backend fixture 覆盖离屏回退；不能据此宣称原生多显示器通过。若工作区小于最小窗口约束，记录实际结果并作为阻塞报告。

额外边界：代码字号 11/19 的按钮禁用、跟随模式下小数字号、转显式字号的取整步进、改变界面字号后仍跟随；这些必须以现有 `code_font.go` 语义为准，HTML 的示例控件不作为存储语义依据。

## Acceptance steps

1. 设计批准后实施；代码独立审核先于最终原生验收。

## Risks and rollback

- 最大宽度与禁止全屏是用户可感知的行为变更，需在设计批准中明确包含；否则回到替代方案重新设计，不能悄悄实施。
- MyGo 对已保存几何和系统 Zoom/Full Screen 的处理可能因平台不同；先用新几何键规避旧状态，原生验证仍不可省略。
- 缩窄窗口时帮助文案、长字体名、长设置路径和更新错误不可压扁标签；控件整组换行、路径可选择且保留完整访问方式。
- About 改布局容易漏掉更新状态动作；状态矩阵必须逐个匹配当前实现。
- 回滚仅撤销该次已提交的设置重设计代码与布局测试，恢复旧 `settings` 几何键和布局。新几何记录可以保留为未使用项，不删除用户配置。上一轮主侧栏 History 的移除是独立变更，不混入回滚。
