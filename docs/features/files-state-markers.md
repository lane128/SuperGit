# Files Git 状态标记三版设计

Status: Approved and implemented（A 前置空心徽章 + 固定内置 Inter Bold；原生验收及本机安装结果见验收记录）
Date: 2026-11-24
Related: [详情标签栏设计](detail-tabs-redesign.md)
Tier: T3。最初要求三版设计，随后用户批准“按照这个实现，修改完成后，安装到本机”。批准范围为 A 前置空心徽章，Files 与详情 tab 使用固定内置 Inter Bold，保证字形来源一致；未授权 commit/push/release。

## Background and goal

Files 当前以分组和右侧方框呈现暂存状态，但普通文件行没有显示 A/M/D 等修改类型。目标是在扫描文件时即可区分新增、修改、删除等状态，同时保留暂存操作的独立语义。

依据现有代码：`file_row.go` 的共用行高为 29 DIP、字号为 12 DIP；`workspace.go:fileRow` 的暂存操作为 22 DIP 命中区域、12 DIP 图标，空框/勾选/减号分别表示未暂存/已暂存/部分暂存。冲突行已有 !，历史提交和 revision compare 行没有暂存操作。实际状态应复用 `statusCode(entry, staged)` / `changedFileCode(status)`，不能从路径或分组标题猜测。

## Non-goals

- B/C 与字体候选保留为设计探索记录；实施只包含已批准的 A 方案及固定字体，不新增其他布局或设置。
- 不改变 Git 写入、暂存权限、文件身份、排序、选择、多选、上下文菜单或差异范围。
- 不新增产品设置。预览的主题、字号、语言、场景与栏宽控件，以及底部选中文件语义说明，均仅用于审核。
- C 是行高与名称布局的扩展备选；需要明确选中该方案后，才把双行布局纳入实施范围。A/B 保持既有行高和路径省略策略。

## Approach

本地可打开预览：[files-state-variants.html](../../design/files-state-variants.html)。`design/` 与截图所在的 `build/` 均为本地忽略目录。

| 方向 | 结构 | 行高 | 状态样式 | 代价 |
| --- | --- | --- | --- | --- |
| A 前置空心徽章（推荐） | 状态 → 文件路径 → 暂存 | 29 DIP | 18 DIP、1 DIP 同色描边、4 DIP 圆角、透明底、11 DIP/800 等宽字母 | 增加一个徽章和间距，压缩路径显示空间 |
| B 尾部独立状态列 | 文件路径 → 状态 → 暂存 | 29 DIP | 与 A 相同，状态列固定宽度 | 文件名起点不变；徽章与暂存方框相邻，需要区分静态标记和操作 |
| C 双行文件信息 | 文件名/父目录 → 字母与状态全称 → 暂存 | 44 DIP | 无边框的粗体字母和本地化全称；窄栏只保留字母 | 路径更清楚，但行高增加约 52%，相同高度约少显示三分之一文件行；属于额外布局变化 |

推荐 A：延续用户已批准的详情标签空心风格，兼顾状态辨认和现有紧凑密度。B 不节省总水平空间，只改变信息顺序。C 以阅读密度换取路径与语义解释，不作为默认实施方向。

### 字母字体候选

用户推荐 A 后要求为徽章字母多配几种字体。预览新增“A · 字母字体”对比区，加载仓库内真实的内置字体文件，而不是用浏览器默认字体代替。每个候选同时显示 11 DIP 实际尺寸和 2.4× 放大样本；点选任一候选，三版徽章同步切换。

| 候选 | 可用性 | 说明 |
| --- | --- | --- |
| 跟随代码字体（推荐） | 现状行为 | 详情标签徽章已使用 `patchFontFamily()`；复用同一来源，用户换代码字体时两处一起变 |
| JetBrains Mono（固定） | 内置 | 不随代码字体设置变化；适合希望状态标记外观恒定 |
| SF Mono | 系统 monospace 解析 | 更接近 macOS 原生；实际字形由系统决定，跨机器可能不同 |
| Geist Mono | 内置 | 字形紧凑，11 DIP 下留白更均匀 |
| Fira Code | 内置 | 字面略宽、形态更圆 |
| IBM Plex Mono | 内置 | 人文风格，笔画对比稍强 |
| 跟随界面字体 | 系统 UI 字体 | 未改界面字体时为 SF Pro（macOS）；若界面字体改为 Inter / Geist / IBM Plex Sans，字母随之变化且更细。非等宽，墨量最大，但与文件名同族，可能削弱状态标记的独立性 |

内置等宽只包含 Regular / Bold 两档，代码请求的 800 字重实际落到 Bold。11 DIP 下单字母墨迹宽约 7.1–8.6 DIP、高约 8.8–9.0 DIP，均远小于 18 DIP 徽章的内沿，不需要为字体调整徽章尺寸。

“跟随界面字体”不是单一字体：应用默认不指定 family，由 AppKit 的 `systemFontOfSize:weight:` 解析为 SF Pro，支持到 800 字重；若用户在设置中把界面字体改成内置的 Inter / Geist / IBM Plex Sans，这些字体只注册了 Regular 与 SemiBold，800 会落到 SemiBold，字母明显更细。因此该选项的观感取决于界面字体设置，不能保证固定。SuperGit 目前只构建 macOS，不存在 Windows / Linux 端的字形差异；macOS 不同版本之间 SF Pro 属同一字体家族，仅随系统版本有细微字形更新，小字号使用 SF Pro Text 光学尺寸。徽章字母均为拉丁字符，不受中文回退到 PingFang SC 的影响。

初轮推荐过“跟随代码字体”；用户随后明确希望无衬线字母跨平台保持一致，因此最终批准并实施固定 Inter Bold。预览中的系统无衬线实际为 macOS SF Pro（`.SFNS-Bold`），其许可不允许随应用跨平台分发。采用官方 Inter 4.0 静态 Bold（700），独立注册为 `SuperGit Status Text`，Files 和详情 tab 共用，不受代码字体/界面字体设置影响。组件请求 800 时匹配内置 Bold；不承诺不同平台抗锯齿像素完全相同，且本轮仅在 macOS 实测。完整 OFL 1.1 与版权声明位于 `internal/lobedesk/fonts/OFL.txt`，`make app` 在签名前将其复制为 `Contents/Resources/Font-Licenses.txt`。

### 共同语义

- A 新增、M 修改、D 删除、? 未跟踪、R 重命名、C 复制、T 类型变化、! 冲突、S 子模块。
- 冲突和子模块优先级沿用既有代码；S 并不表示普通文件的修改类型。
- 已暂存行对应 HEAD → Index，未暂存行对应 Index → Working tree。未跟踪文件没有可比较的 Index 内容；历史提交沿用原有比较范围，预览用普通单父提交作为示例。
- 同一路径可同时出现：示例先将新文件暂存为 A，再编辑工作区，未暂存行显示 M；两行暂存按钮均为部分暂存。
- 标记不获得按钮行为；完整路径、状态字母、本地化含义及当前暂存版本应进入 tooltip/辅助功能说明。
- 冲突行以新状态位置显示一个 !，替代现有重复标记，不新增暂存按钮。为保持 B 状态列对齐，预览保留空操作槽。
- 子模块示例选取受保护情形，显示禁用操作；实施必须沿用实际 `fileActionTarget` 判断，不能将所有 S 行一律禁用。
- 历史提交和 revision compare 使用同一方向，不显示或预留暂存按钮。

### 颜色与尺寸

- 使用现有 A 绿、M/T 琥珀、D/! 红、? 蓝、R/C/S 紫语义。文字和描边同色，不能仅靠颜色传达状态。
- A/M/D 对普通、hover、选中背景目标 ≥7:1，其余字母 ≥4.5:1。HTML 使用两套示意配色；原生实施应复用局部对比度校正策略，覆盖所有支持的主题，不能把预览色值当作所有主题的固定值。
- A/B 名称沿用逐层去除前导目录的省略策略，完整路径在悬停说明保留；不引入新的中间省略算法。
- 暂存命中区域保持 22 DIP，图标保持 12 DIP，字母与行高随字号缩放。96 DIP 是压缩边界检查，不是可读性最优尺寸。
- C 在预览容器内容宽度约 220 DIP 以下隐藏状态全称；该阈值和双行滚动/命中适配须在选择 C 后做原生验证。

## Impact

实施预期涉及 `file_row.go` 及调用者 `workspace.go`、`history.go`、`revision_compare.go`；可提取共用状态标记 helper，参考 `detail_tab_style.go` 的空心徽章、颜色与语义帮助函数。不得通过修改共享标签样式意外影响仓库 tab 或详情 tab。

兼容性：不改变状态模型或 Git 比较规则，无持久化、迁移、签名、权限修改。C 若选中，需审查所有依赖 `fileRowHeight()` 的可视范围、定位及滚动计算，不能只增大绘制高度。

## Test plan

本轮设计检查：

- `node build/check-files-state-design.cjs`：4 场景 × 5 栏宽（300/240/180/130/96）× 2 字号 × 2 配色 × 2 主题 × 2 语言 = 320 配置，每配置同时检查三版，共 960 布局。
- 检查行高、实际栏宽、状态/名称/暂存槽边界、横向溢出、冲突无暂存按钮、受保护子模块禁用、历史无暂存槽、空状态。
- 144 次状态对比度检查；A/M/D 最低 7.14:1，其他状态最低 5.70:1。
- 7 个字母字体候选：断言实际字族生效、徽章内单字母墨迹不超界（1.15 字号下宽 7.1–8.6 DIP、高 8.8–9.0 DIP，对内沿 16 DIP）、四个内置字体文件加载成功、字体卡选中态唯一。
- 点击同步选择、已暂存/未暂存比较范围、方向键/Home/End、暂存演示按钮不改变文件选择；375/400px 页面无水平溢出；无 JavaScript 错误。
- 已查看默认浅色与大字号深色窄栏截图。截图为设计稿，不代表原生 MyGo 验收。

实施获批后的单元/回归测试：

- 所有状态映射、冲突/子模块优先级、同一路径 Index/Worktree 不同状态。
- 工作区、历史提交、revision compare 三个入口一致；状态静态展示不截获原有行选择、双击、右键、多选或暂存动作。
- 窄栏、大字号、中英文、长路径、同名不同目录、组合字符、选中/hover/focus；暂存按钮仍完整可点击。
- 状态 tooltip/辅助功能说明完整；原有可访问名称和快捷键兼容。明确覆盖 Enter/Space 对两个部分暂存行的暂存/取消暂存动作；HTML 中 Enter/Space 仅演示选择，不证明原生暂存快捷键兼容。
- 若选 C，补双行高度对应的滚动定位与命中测试。
- T3 实施执行 gofmt、go vet、一次完整覆盖率测试，独立代码审查先于原生验收。完整覆盖率通过（lobedesk 85.7%）；许可证与测试跟进仅重跑 vet 和定向测试，具体命令及范围见验收记录。

## Acceptance steps

1. 用户选择并批准设计后再实施。
2. 完成回归测试及独立代码审查，执行 `make app`。
3. 在隔离测试仓库中检查两套配色、浅深色、两字号及实际 Files 窄栏；对照已选方案检查状态、选择、暂存按钮、冲突、受保护子模块、提交和 revision compare。
4. 原生自动化如需调用暂存，只操作隔离 fixture，记录 HEAD/Index/工作区预期变化；不使用用户工作仓库验证写入。
5. 在 `docs/acceptance/<YYYY-MM-DD>/` 记录原生截图、边界、交互、未覆盖范围，等待用户验收；安装、提交和发布另需授权。

## Risks and rollback

- A/B 占用名称宽度；B 容易将右侧空心字母误认为可点击控件；C 牺牲行密度并扩大高度相关回归范围。
- 浏览器字体、布局与原生 MyGo 不同；HTML 通过不能替代实际 app 验证。96 DIP 下名称会被大幅截断。
- 原生 22 DIP 暂存目标沿用当前桌面交互，不宣称达到移动端触控目标。
- 本机安装前保留旧 App 备份；需要回滚时可恢复旧 bundle，不改变用户仓库或偏好。源码回滚仅撤销 Files 标记、固定字体与字体许可证打包改动，不隐式撤销先前详情标签重设计。

## Design review and evidence

独立 reviewer 在隔离 worktree 中完成有界只读审查，无设计阶段 must-fix。建议已纳入：未跟踪文件的预览说明改为“无 Index 基准内容”，显式补充 Enter/Space 暂存回归，并要求实施验收前补齐可复现 fixture。审查只读设计与直接相关代码，未运行测试或渲染；浏览器验证由主流程完成。随后用户已授权实施和本机安装。独立代码审查未发现运行时缺陷，要求补齐完整字体许可证与正确版权年份；已补齐并加入 App 资源。

实施验收前需补充 fixture 脚本和预期状态快照：新文件 add 后再次编辑形成 Index A/Worktree M；分支双方修改同一行产生冲突；提交基准后移动文件产生 R；C/T 使用 Git 支持的可重复状态 fixture，注明检测参数与文件系统能力；子模块分别覆盖 dirty 受保护、可暂存 gitlink 变化及可取消暂存的 gitlink。每个 fixture 记录 porcelain/changed-file 输出与动作后预期，不能以示意数据代替实际 Git 验证。
