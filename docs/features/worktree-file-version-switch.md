# 在文件 Diff 中核对已暂存与未暂存改动

## 使用场景

同一文件同时有准备提交的修复和要留在本地的调试日志。用户在历史页选中工作树，从 Files 只打开未暂存的文件标签，希望在阅读位置直接核对暂存的修复，然后切回继续拆分。

## 本轮范围

- 产品角色核对了现有入口。Files 两个分组和提交总览都能分别打开同一路径的两个版本。现有标签按路径和暂存状态区分，文件头已显示比较基线。
- 在工作树的单文件 Diff 文件头提供查看另一版本的入口。以当前状态中同一路径的可用版本为准。历史提交、冲突和仅有一个版本的文件沿用原有文件头。
- 复用文件标签导航。首次查看打开另一版本，随后激活已有标签。切换仅浏览，不执行暂存操作，不改提交草稿。

## 验收场景

1. 在同一文件的两处分别加入修复 A 和日志 B，仅暂存 A。只打开未暂存标签，能从文件头查看已暂存的 A，并切回 B。
2. 多次往返始终只有两个对应的文件标签。核对两个版本各自的滚动位置，旧版本的选行不能作用于新版本。
3. 对侧 Files 分组折叠时仍能切换。外部修改使对侧 Diff 消失并刷新后，入口应随状态收起。
4. 鼠标与键盘均可完成切换。中英文、窄栏及长文件名下，能分清只读的查看动作和写入暂存区的动作。
5. 对比浏览前后的 HEAD、索引内容、工作树字节和提交草稿。
