# 差异区的两套选择模型

差异区同时支持「按行选择」和「按文字选择」。它们服务不同的动作，状态也各自独立；混用时需要知道谁先拿到按键。改差异行交互前先读这份规则，验收用例见 `TestAContextAnchorDragSelectsOnlyChangedLines`。

## 1. 按行选择：为动作选目标

**抓手是左侧行号**（`lineGutterLabel` 那个按钮），不是代码文本。

| 操作 | 工作区补丁（可写） | 提交补丁（只读） |
| --- | --- | --- |
| 单击行号 | 只选该行；该行必须是增／删行 | 选该行；增、删、上下文行都可以 |
| Shift + 行号 | 从锚点扩到该行，区间内只收增／删行 | 从锚点扩到该行，区间内收所有可选中行 |
| ⌘ + 行号 | 切换该行，锚点移到该行 | 同左 |
| 在行号上拖动 | 从按下行扩到指针越过的行，区间内只收增／删行 | 同左，但收所有可选中行 |
| Esc | 清空行选择 | 清空行选择 |
| ↑ / ↓（已有行选择时） | 在增／删行之间移动，Shift 扩展 | 在可选中行之间移动，Shift 扩展 |
| ⌘C | 复制选中行（仅在有行选择时注册） | 同左 |

- **为什么工作区只收增／删行**：行级动作只有暂存、取消暂存、丢弃、复制这几种，上下文行没有可执行的语义。区间里的上下文行会被跳过，而不是让按钮对一个无法暂存的行发亮。
- **从上下文行号开始拖**：按下本身不选中任何行（上下文行 `clickLine` 直接返回）；指针越过增／删行时，按「起点 → 当前行」的区间建立选择，仍然只收增／删行。这是有意的边界，不是拖拽丢失。
- **右键**：在选区之外右键会先把该行选成唯一选区，再弹出该行的菜单；在选区之内右键保留整个选区，菜单作用于全部选中行。
- **锚点与游标**：`lineAnchor` / `commitAnchor` 是 Shift 与拖动的起点，`lineCursor` / `commitCursor` 是当前行；方向键从游标继续走。

## 2. 按文字选择：为复制选内容

代码文本是独立段落（`diffCodeRole` 标出增删方向），拖动它选的是字符，和行号按钮不是同一个控件。因此：

- 拖文字不会改变行选择，拖行号也不会改变文字选区。
- 两者可以同时存在。**⌘C 归行选择所有**：只要当前补丁存在行选择，窗口就注册行复制的 ⌘C；没有行选择时 ⌘C 不注册，交给系统复制正在拖选的文字。这是两套模型唯一会互相影响的地方。
- Lobe 切换详情标签或关闭当前文件标签时清空行选择；隐藏整个详情或历史补丁时也清空。永久「提交 / 摘要」标签包含补丁，处于该标签时仍可选择其中实际显示的行。文字选区随内容重绘自然消失。

## 3. 什么时候两套选择都清空

- 切换文件（工作区）：`selectFile` 清 `lineSel`；重新读取补丁成功后也清一次，避免旧行号指向新内容。
- 切换提交：`setSelectedCommit` 在 SHA 真正变化时清 `commitSel`，并清签名状态。
- 清空搜索、重新走历史、切换引用：会替换提交列表与详情，行选择一并清空。
- 同一文件内容因自动刷新而变化：补丁重新读取后行选择清空。Lobe 工作区总览每次开始新的读取批次都会清空旧行选择，即使最终内容相同；后台单文件读取不会清空当前总览的有效选区。

### Lobe 标签与总览的目标隔离

- 工作区文件标签以原始路径和已暂存 / 未暂存分组区分；历史标签绑定当前仓库及完整提交 SHA。相同文件名不会合并成同一个目标。
- 工作区总览的一次行选择只属于一个文件版本。切到另一个文件或分组时重新建立选择，复制与暂存操作使用选区绑定的差异快照。刷新或目标过期后拒绝沿用旧快照；执行写入前后端仍检查实际差异。
- 历史文件标签只允许选择该文件的可见补丁；摘要可选择全部展开补丁。全选、反选与范围选择不会包含隐藏文件或折叠块中的行。
- 折叠工作区总览补丁会清空行选择。总览的行 / 片段菜单支持暂存和取消暂存；丢弃仍从独立文件视图进入原有确认流程。

## 4. 已知边界

- 上述行号拖动规则适用于原有单文件视图与历史补丁。Lobe 工作区总览目前支持单击、Shift、⌘ 与键盘行选择，尚未接入行号拖动；代码文本仍支持原生文字选择。

- 提交补丁的行选择包含上下文行，但行级动作是只读的（复制片段、复制行、查看 blame），所以不存在「选了不能操作的行」。
- 工作区补丁里没有「全选」菜单项以外的整段选择：全选与反选在差异区右键菜单，作用于增／删行。
- 文本选区不可跨行号按钮继续扩展；想跨段复制用行选择。
- 两套模型暂不统一（是否会合并成一套等使用反馈）。如果统一，优先保留「行号选行、文字选字」的分工，只把清空时机对齐。
