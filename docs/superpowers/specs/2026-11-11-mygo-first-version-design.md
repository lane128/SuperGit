# SuperGit 原生首版设计

## 目标与授权

用户在完成两轮 Git GUI 设计评审后明确选择 MyGo，并要求先实现一个可运行版本。当前目标授权直接在本会话实现和运行；不要求再次选择执行方式。macOS 优先，后续考虑 Windows / Linux。用户当前使用 Sublime Merge，关注流畅度、现代界面与可定制性；submodule 是核心要求。

## 当前交付

使用 Go 1.27.3、MyGo v0.8.3 原生 GPU UI 与系统 Git executable；不使用 WebView 包装设计稿。默认不打开或修改用户仓库，提供原生目录选择及命令行路径参数。用户选择仓库后读取真实状态；只有明确点击写操作才暂存、取消暂存、检出或提交。

界面保留设计稿的三栏结构：仓库导航、文件与提交区、Diff。提供工作区、历史线图、分支、worktree 与 submodule 页面。历史选中提交联动文件与 Diff；submodule 区分父仓库 HEAD 指针、Index 指针、子模块检出与内部改动，可进入子模块并返回父仓库。

首版可执行：打开仓库、刷新、按文件暂存/取消暂存、普通文本按片段暂存/取消暂存、提交、查看历史和 Diff、查看本地分支与 worktree、进入子模块。主题和代码字号可调整。操作后台执行，结果回主线程，错误可见；只读刷新允许合并，写操作在应用内串行。

不把设计稿中的全部功能假装已经实现：行级暂存、复杂 rebase、内置三方合并、clone、stash 管理、自动更新及远端发布流程不属于当前版本；冲突状态仍准确显示。UI 不显示可点击但没有实际行为的产品操作。

## Git 执行约束

- 使用 os/exec 参数数组，不调用 shell，不拼接命令字符串执行。
- 文件参数使用 `--` 分隔；支持空格、中文、换行、重命名和前导短横线。
- 使用 porcelain v2 的 NUL 格式解析状态；不能按空格拆文件名。
- Diff 禁止 external diff / textconv；限制输出大小；不在 UI 线程运行 Git。
- 取消暂存必须保留工作区内容；初次提交前的 Index 也能操作。
- 提交仅包含 Index，保留 Git hooks 和失败输出，禁止隐式 add --all。
- 子模块内部未提交内容不会随父仓库提交；进入未初始化目录不能误发现父仓库。
- 片段暂存仅用于普通已跟踪文本文件；新建、删除、重命名、冲突、二进制和仅模式变化采用文件级操作。
- 历史连线源于父 SHA，不绘制伪时间线；缺失父提交视为分页边界。
- 不自动 pull、push、reset、discard 或初始化子模块，不删除用户内容。

## 验证与交付

使用临时真实 Git 仓库验证状态解析、暂存、片段应用、未出生分支、提交范围、hook 失败、重命名特殊路径以及子模块指针。应用状态测试验证异步过期结果处理与忙碌写操作保护。运行 go test、go test -race、go vet、构建 macOS 二进制，并实际启动原生窗口；使用本任务生成的演示仓库完成使用检查。保留旧设计稿、不 commit、不发布。
