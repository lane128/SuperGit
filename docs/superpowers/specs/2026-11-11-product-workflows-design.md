# SuperGit 完整产品工作流演进

用户目标：继续按照完整 Git GUI 产品目标开发。沿用已有完整设计稿，不重新请求执行授权；先完成真实日常开发闭环，再逐步完善进阶编辑与发布品质。MyGo 原生 Go UI、macOS 优先、submodule 一等支持不变。

## 本次演进

1. 仓库入口：初始化与克隆到不存在的新目录；最近仓库与外观偏好持久化。克隆不隐式递归初始化子模块。
2. 分支：创建、切换、重命名、安全删除、远端跟踪分支创建。变更工作树的操作先检查工作区；有改动时明确要求先提交或 Stash，不隐式丢弃。Git 保留其他 worktree 占用检查。
3. 远端：URL/跟踪分支浏览、添加远端、Fetch、仅快进 Pull、普通 Push 和首次设置 upstream。Push 明确显示远端、源分支、目标分支并由用户确认。默认从不强制推送；子模块引用使用 Git --recurse-submodules=check，包含无需新增父提交但需推送的情况。
4. Stash：保存（可包含未跟踪文件）、列表、Diff 检查、应用、应用后移除与明确确认后的删除。按不可变 SHA 选择，列表索引变化必须拒绝误操作；恢复前要求工作区干净，发生冲突时保留 stash。
5. Merge / Rebase / Cherry-pick / Revert：执行前检查干净状态与进行中的操作。显示进行中操作、冲突文件及继续 / 中止。优先实现普通 rebase；可视化交互式计划单独迭代。
6. 冲突：展示 base / ours / theirs，允许编辑最终结果，保存并标记解决；内容仍含冲突标记时拒绝标记；二进制/删除冲突交给文件级选择，禁止当文本盲写。
7. Worktree：新建独立路径与分支、安全移除已清理且未锁定的其他工作区；不提供 force remove。Submodule：显式初始化／同步到 Index 指针；检查脏状态并保留 dirty，不自动更新到 remote HEAD。
8. 历史：搜索已载入提交、继续加载、提交详情与父 SHA 保持一致，支持安全的 cherry-pick / revert 入口。

## 执行边界

全部仓库操作由 typed gitrepo API 执行，参数数组和 literal pathspecs；不让 UI 传任意 shell。所有写操作后台串行；repo generation 防止旧结果污染新仓库；操作期间禁止切换与第二次写。新增的操作确认均为真实写操作的必要交互，不新增无行为的按钮。网络认证使用系统 Git 的凭据 helper／SSH agent；不存储或要求输入令牌。对外实际操作只有用户在应用中明确选择后才执行；开发只使用新建的本地 bare remote 和临时仓库，不对用户远端执行 push。
