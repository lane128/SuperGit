# Create Local Lightweight Tag Implementation Plan

**Goal:** Create a local lightweight tag at the selected history commit after explicit name/SHA confirmation, refusing existing tags and preserving all working state.

**Spec:** Existing full Git GUI product authorization; docs/superpowers/specs/2026-11-11-product-workflows-design.md immutable history targets and typed/confirmed writes. This iteration adds a bounded local-reference workflow, with no remote publishing.

**Architecture:** Repository.CreateTag(ctx, name, sha) serializes the write, validates the full refs/tags name and exact commit OID, and uses system Git's atomic `update-ref --no-deref --stdin` create transaction. This refuses every existing ref, including dangling symbolic tags, and creates a direct lightweight ref independent of signing configuration. The action draft captures selected SHA; form exposes only name and read-only target, confirmation states local/lightweight/no-overwrite behavior, existing action generation/HEAD protections apply. Refresh uses existing tag decorations in history.

**Constraints:** No project commit/push/publication or user repository writes. Backend/native tests use temporary local repos; creating fixture refs/commits is explicit test setup. No tag overwrite/delete or remote push. No annotation/signature UI in this slice. Preserve real Git reference hooks. No global Git config changes; repository tag.gpgSign must not turn this explicitly lightweight operation into signing/annotation.

**Review focus:** Target remains selected SHA even when form/history/HEAD moves. Invalid names/options/missing or non-commit OIDs must not write refs. Same-name lightweight/annotated/symbolic tags cannot be overwritten. Dirty Index/worktree/HEAD remain unchanged; an already-cancelled context leaves no ref. An in-flight Git write may complete before cancellation, following the existing refresh/inspect-results contract. Form/confirmation cancellation never writes; target generation changes refuse execution. Existing historical actions must fit at narrow widths.

- [x] Backend RED→GREEN: valid Unicode/nested tags at immutable older commit, dirty-state preservation; invalid name/OID/noncommit/missing/canceled rejection; existing tag and symbolic ref preservation, explicit lightweight despite signing config.
- [x] Action/UI tests and implementation: immutable selected-SHA draft, editable name only, concrete confirmation, dispatcher and history button with wrapped action row.
- [x] Native fixture: create on an older SHA with staged/unstaged draft present, cancel/no-write, duplicate failure/no-overwrite and tag decorations; independent source review, full Go/race/vet/app/native checks, logs/screenshots/README and next loop.
