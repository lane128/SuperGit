Goal: measure larger repository cost and make repeated history frames reuse filtering/layout and paint only graph edges that intersect the visible row. Preserve actual parent SHA connections, merge lanes, boundary marks and original commit selection indices.

Investigation: history currently filters/allocates on every frame and rebuilds the filtered DAG every frame; each visible graph cell scans all rows to calculate width and all edges to find intersecting spans. Snapshot history is capped at 2,000. Measure before optimizing; do not claim whole-app frame speed from a pure model benchmark.

Design: cache the history presentation by repository snapshot revision plus normalized query; invalidate on every accepted snapshot/repository change. Store filtered commits, original indices, graph rows, width, and an interval index over original edge spans. A max-end interval index prunes subtrees whose spans cannot cross the row, retaining original edge order with O(E) storage, without expanding a long edge into every crossed row. Query work is O(E) in the worst case (for example, many crossing edges); no universal O(log E + crossings) bound is claimed for this implementation. This is presentation-only; Git semantics and limits remain unchanged.
