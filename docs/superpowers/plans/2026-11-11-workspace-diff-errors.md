# Workspace Diff Errors Implementation Plan

**Goal:** Display workspace Diff failures and a read-only retry for the exact selected raw path and Index/worktree group, without treating errors as empty Diff or enabling stale line actions.

**Spec:** docs/superpowers/specs/2026-11-11-product-workflows-design.md (accurate workspace state, isolated reads and protected Index writes).

**Architecture:** Keep the existing cancellable `diff` lane. Typed requests capture ticket/path/staged; explicit loaded/error state distinguishes successful empty Diff, failure and interruption. Begin/finish helpers own lifecycle and cancellation. New targets/repository acceptance clear old errors, automatic unchanged successful reads keep existing line selection/scroll, failure clears unusable Diff and selected lines. The view provides local error/retry; watcher can recover a failed preview even when a successful read returns empty text.

**Constraints:** No project commit/push/publication or user repository writes. Test only fresh local fixtures. Do not reset ListState in callbacks. Preserve keyboard, editing focus, commit draft, historical Diff/message and line-level protection. One independent narrow read-only source review.

**Review focus:** Same path in two groups must never share results/errors. Failed reads cannot enable line/hunk actions or expose partial data. Old ticket/repository/path/group callbacks cannot publish or cancel the current read. Opening/writing/closed block starts; interrupted empty previews remain retryable. Automatic unchanged reads retain selection, changed/failed reads clear it. A clean fallback/new repository must not show old errors.

- [x] UI and real-window verification: error/retry with captured path/group; oversized worktree and Index Diff cases, retry/navigation/recovery and unchanged repository data during browsing.
- [x] One independent review, full Go/race/vet/app/native checks, screenshots/logs, README and next dynamic iteration.
