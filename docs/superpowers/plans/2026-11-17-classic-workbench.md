# Classic Three Column Workbench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the selected A classic three column design as a polished, usable Git GUI, preserving existing Git correctness and keyboard workflows.

**Architecture:** Retain Go/MyGo, the Lobe preview entrypoint and `internal/gitrepo`. Deliver the supplied redesign in independently verified increments: shared appearance first, settings and feedback second, then navigation and the complete three column workspace. Two isolated review agents cover product and design; the implementing agent also owns user workflow testing.

**Tech Stack:** Go, MyGo, Lobe MyGo, native automation, Git fixture repositories.

**Spec:** `design/workbench-redesign/UI-Spec.md`, with layout A selected by the user on 2026-11-17.

## Global Constraints

- Preserve main window minimum 980 × 640; settings minimum 560 × 480 and default 820 × 720.
- Preserve saved palette keys, split fractions, draft content, file version identity, keyboard commands and virtualized lists.
- Reuse root/generation/path/staged/SHA guards for Git writes. Confirmations and feedback retain originating window and repository ownership.
- New design uses a named SuperGit palette with system/light/dark modes. UI sizes use logical points and existing font scaling.
- Work in `cmd/supergit-lobe` and `internal/lobedesk`; switching the packaged app requires separate migration verification.
- Do not commit or publish without explicit user approval. Existing README and untracked design files belong to the user and must be preserved.
- Cross-platform behavior is a goal; native evidence from macOS does not establish Windows or Linux support.

## Review Focus

- Same file with staged and unstaged bytes: selecting and acting on each version must retain its original target.
- Narrow windows, long paths and 1.15 font scale: active tab, close controls, commit and sync actions remain reachable.
- Settings palette changes and restart: both windows use the same palette, legacy keys still resolve, saved preferences survive.
- Modal dialogs and repository switching during background operations: stale actions are rejected and old feedback does not migrate.
- Large histories and change lists: layout and styling preserve virtualization, scroll positions and loaded parent boundaries.
