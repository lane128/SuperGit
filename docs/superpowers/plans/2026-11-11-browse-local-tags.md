# Browse Local Tags Implementation Plan

**Goal:** Browse and search local tags in the existing branches page and inspect exact commit targets even outside loaded history, preserving all repository data.

**Spec:** Existing full Git GUI product authorization and docs/superpowers/specs/2026-11-11-product-workflows-design.md immutable history/read isolation. Continues completed local lightweight tag creation.

**Architecture:** A single bounded system-Git for-each-ref query returns typed tag identity, direct/peeled object types and commit metadata. Snapshot carries tags and its distinct error. Branches page adds a searchable bounded virtual list with local error/empty/no-match states. A read-only tag action captures metadata from the current accepted snapshot, pins a selected commit without adding fabricated graph rows, clears history search, and reuses independent message/files/Diff reads. Existing loaded history metadata takes precedence over a matching pin; accepted repository switch clears it.

**Constraints:** No project commit/push/publication, user repository writes or tag deletion. Only fresh local fixture refs/commits. No new sidebar page/settings. Preserve native list lifetime: search callbacks request deferred reset. No per-tag subprocess loop. Plain and annotated commit targets support commit inspection, including nested tags: Git's dereferenced atoms recursively peel them in the single query. Missing-object reads, malformed returned records and read limits surface as errors, never successful empty results. Git silently skips dangling symbolic refs; the UI and API explicitly limit the inventory to resolvable tags (see final ruling).

**Review focus:** Exact full tag names despite ambiguous branch names/Unicode/nesting; annotated tag object OID differs from commit OID; blob/tree targets cannot be treated as commits; nested annotated tags retain their own object OID while exposing the final peeled commit; symbolic tags are labeled honestly. Older commit details must work outside initial 300 records without changing the graph traversal/order. Stale tag callbacks reject after accepted snapshot changes; pin is cleared on repository switch and replaced by explicit history selection. Browsing/search/navigation must leave HEAD/Index/working bytes/refs/remotes untouched. No callback ListState destruction.

- [x] Backend: typed Tags API and real Git tests for lightweight/annotated/symbolic/noncommit/nested refs, exact commit metadata, no-write/cancellation/empty/corrupt-ref failure.
- [x] Desktop: snapshot error isolation, searchable virtual tag list with distinct states, immutable tag metadata selection/pin and current-snapshot/busy guards; tests first and integration.
- [x] Native --tags extension: empty/search/object type, older unloaded commit details, error/recovery/read-only checks; independent source review, full Go/race/vet/app/native regression, final logs/screenshots/README and next loop.

## Evidence and rulings

Existing branches view has no tag inventory; historical tag decorations require finding the commit first. Existing commitDetails only finds selected metadata in loaded history, so directly selecting an older tag target needs an independent metadata pin. A temporary-repo probe verified for-each-ref direct and dereferenced parent/subject/author/date atoms return exact commit metadata in one query.

Ruling: use Git's peeled metadata in the bounded batch query — supports lightweight/annotated/nested release tags without a subprocess per tag — cost: annotation text/signature details are not read; only tag object identity and final target metadata. Noncommit targets are displayed, never treated as commits. Initial test assumed dereferenced atoms peel one level; a real nested-tag test failed that expectation. A separate isolated raw cat-file/for-each-ref probe confirmed Git recursively peels nested tags, so corrected the test and scope to expose the exact final commit while retaining the outer tag OID.

Ruling: preserve the real paged DAG and hold only one exact commit metadata pin for tag inspection — avoids manufacturing graph rows or auto-loading an unbounded traversal — cost: the inspected commit can have no selected graph row until its page is loaded. The UI explains this and existing explicit history selection replaces the pin.

Backend test-first cycle passed: `go test ./internal/gitrepo -run '^TestTags'` initially required the missing API, then covered exact object/commit metadata, lightweight/annotated/nested/symbolic/tree/blob tags, Unicode names and ambiguous branch names, cancellation and missing-object failure without repository writes. Desktop test-first cycle passed four groups: immutable unloaded-target pin, stale/busy guards, Unicode/name/both-OID filtering with deferred ListState reset, and auxiliary tag failure preserving usable workspace status.

Native `--tags` passed seven groups in `build/browse-tags-native.log`. The new branch-insertion focus assertion first failed (`build/browse-tags-search-focus-red.log`); adding `c.Key("tag-search")` to the search input preserved identity and made it pass. Existing four creation groups remain. Three browsing groups cover distinct states/types, a target outside the first 300 of 360 commits and nested tag inspection without fake graph rows, and missing-object failure/read-only retry/fixture repair. Viewed empty, annotated, unloaded-commit and read-error screenshots from that initial run; final full-suite screenshot checks are recorded below.

Final independent source review: one fresh read-only Opus reviewer, no edits/tests/build/native execution. Two concrete findings: dangling symbolic tags omitted by Git enumeration (P2), and an unloaded notice remaining after pagination loads its selected commit (P3). No re-review dispatched.

Final: Ruling: the batch query cannot diagnose dangling symbolic refs, which Git silently omits — confirmed in real empty/mixed fixtures (`build/browse-tags-dangling-red.log`), then retained a characterization test and changed API comments, UI scope/empty copy and README to promise resolvable tags only. No extra whole-repository integrity scan or files-backend-specific parser was introduced. The regression log is evidence of a rejected stronger contract, not a claim that dangling-ref detection was implemented — cost: dangling tags remain absent; users need external Git diagnostics for raw reference integrity. Missing-object failures still surface distinctly; native fixture now explicitly preserves a dangling tag and checks the scope text.

Final: minor (deferred): `historyIndex` is not reconciled when a later page first loads the pinned tag target, so the unloaded notice can persist until refresh/explicit history selection. Source verification confirms this index only controls that notice; selected SHA, metadata preference, message/files/Diff and graph model remain correct. Documented in README; no claim of fixing this finding.

Final: Ruling: reviewer declined rendered/accessibility/focus behavior and callback timing — main-session native automation and actual screenshot inspection own those checks; source review alone does not establish runtime correctness — cost: unexercised timing and layouts can still differ.

Final: Ruling: reviewer declined runtime races, large-list responsiveness and pending suite completion — full Go/race/vet/app plus native regression are the acceptance checks below; no new tag performance benchmark or exhaustive race schedule is claimed — cost: very large tag inventories and untested concurrent timing remain unmeasured.
