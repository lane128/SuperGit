# Repository Change Detection — Iteration Plan

Directive: /loop 继续按照完整的 Git GUI 产品目标开发，继续迭代. Continue the existing complete Git GUI goal in place; no project Git checkout, commits or publishing. One scoped read-only reviewer after implementation.

Goal: automatically update repository state and the selected workspace Diff after external file/Git/submodule changes, without repeated refreshes while nothing changed or overwriting drafts/conflict editing/confirmation targets.

Design: bounded Git-based polling, every 3 seconds in a focused window and 15 seconds unfocused, also check on focus. Each repository generation has at most one probe in flight. Hash status (including Index blob IDs and child HEAD), refs, worktrees, configuration and operation identity. Read the selected workspace Diff to detect repeated edits to already-dirty files. Git is authoritative for ignored paths, linked worktrees and submodules. No network operations. Probes have a 15-second deadline; failures are visible once, retry later. Capture baseline before each snapshot read so changes during refresh are detected by a later probe.

Automatic refreshes preserve unchanged Diff selection and scroll; changed Diff clears selection. Manual refresh, file/group/repository switches retain explicit selection-reset behavior. Snapshot refresh keeps commit drafts, conflict result text and immutable confirmation targets. Skip probes while opening/reading/writing; reject stale repository results. Stop timers and cancel reads on window close.
