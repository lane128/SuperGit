# SuperGit 页面与状态路线图

主入口是 [全景 SVG](roadmap.svg)，逐页阅读使用 [43 页 PDF](roadmap.pdf)。所有文件均可离线查看，没有网页运行时，也不会执行 Git 操作。

全景包含 8 组、40 个代表性页面状态。每个窗口下方附设计要点和需要进一步展开的关联状态；关联状态清单不表示每个状态都已单独画成窗口。箭头描述触发与去向，跨组跳转使用页面编号。

## 本轮设计规则

- 统一桌面外壳：窗口控制、仓库页签、当前仓库与分支、导航、文件与 Diff、底部状态。示例窗口基准为 1040 × 700。
- 列表选中用窄边与浅底，文件、代码和属性按共同基线对齐；不用营销页面的卡片堆叠表现 Git 对象。
- 历史图使用固定轨道、竖直主线、短折线和 4px 圆角。节点对齐提交行，合并节点双圈。缺失父提交以短虚线和边界标记表示，不补造历史。
- 分支身份同时由轨道、节点和可见引用名表达；绿色轨道对浅色背景的对比有警告，因此不依赖颜色识别。
- 单击子模块只预览。双击已初始化项在同窗口打开独立仓库页签；已打开则聚焦，嵌套路径继续保留面包屑。操作只针对活动仓库。
- 未初始化项先确认路径和 Index 版本。成功后进入子仓库；失败或取消留在父仓库，不提前创建空页签。
- 返回父仓库恢复草稿、选择和阅读位置，并重新读取三指针。子模块提交不会自动暂存父仓库 gitlink。
- 首批语言为跟随系统、简体中文和 English。未知系统语言回退 English。界面和错误摘要本地化，路径、分支、SHA、提交原文、原始 Git 输出保持原样。
- 应用偏好即时预览并保存。Git 身份配置显示来源和当前仓库 / 全局范围，需要明确保存；离开未保存的 Git 表单可继续编辑、放弃输入或保存。

## 阶段与实现边界

所有画板均为新 UI 设计，尚未应用到 MyGo 原生客户端。阶段表示依赖与设计范围，不是发布日期。

- **R1**：底层 Git 能力或对应行为已存在，重新整理界面与状态。
- **R2**：仓库页签、多语言、完整设置及父仓库完整视图状态保存等新增提案。
- **R3**：交互式 Rebase 和外部工具等后续提案。

当前客户端进入子模块会切换当前仓库，并提供返回父仓库；没有仓库页签。当前偏好仅持久化深浅色、代码字号和最近仓库；完整设置、多语言、缩放、密度、快捷键编辑尚未实现。现有提交草稿按仓库保留，选择和滚动位置并未完整恢复。

## 源文件与重新导出

- `catalog.mjs`：页面、状态、流向、设置与阶段清单。
- `primitives.mjs`：原生 SVG 文字、控件、桌面外壳和设置窗口。
- `screens.mjs`：40 个窗口的实际绘制。
- `generate.mjs`：全景、分区、单页和清单 SVG，以及 `manifest.json`。
- `render.mjs`：使用本机 Chrome 和已有隔离 Playwright 渲染 PNG、生成 PDF 并检查 XML、文字边界、外部请求和旧交互稿的直线轨道。

生成矢量文件：`node design/roadmap/generate.mjs`。

导出与检查：`node design/roadmap/render.mjs`。导出脚本沿用本次会话已有的 Playwright 临时安装路径；该目录被系统清理后，需要在独立工具目录准备 Playwright 并更新脚本路径。它不是原生应用的运行依赖。

导出 PDF 所用的临时排版 HTML 位于 `build/roadmap-print.html`，只作为印刷中间文件；主交付是 SVG、PNG 和 PDF。
